# Phase 2 Traceability Matrix: Identity & Merchant Bounded Contexts

| Capability / Requirement | Implementation Files | Verification / Tests | Exit Criteria & Assurance |
| :--- | :--- | :--- | :--- |
| **1. Database Schema Migrations** | `apps/api/src/infra/database/migrations/0001_identity_schema.sql`, `0002_merchant_schema.sql`, `runner.ts` | `apps/api/test/migrations.test.ts` | Forward-only SQL migrations applied in deterministic order. Tables for `tenants`, `users`, `tenant_memberships`, `refresh_tokens`, `security_audit_events`, and `merchant_profiles` are created with strict relational foreign keys and indices. |
| **2. Secure Password Storage** | `apps/api/src/modules/identity/internal/password-hasher.ts` | `apps/api/test/password-hasher.test.ts` | `crypto.scrypt` with per-user cryptographically random 16-byte salt; format `salt:hash`; constant-time verification using `timingSafeEqual`. Zero plaintext password persistence. |
| **3. Server-Controlled Authentication** | `apps/api/src/modules/identity/internal/identity-service.ts`, `token-service.ts` | `apps/api/test/identity-auth.test.ts`, `merchant-flow-isolation.test.ts` | Registration, login, and `/auth/me` endpoints issue dual tokens: signed short-lived access tokens (HMAC-SHA256) and cryptographically secure random refresh tokens. Constant-time dummy hashing on invalid credentials prevents timing attacks and user enumeration. |
| **4. Refresh Token Rotation & Reuse Detection** | `apps/api/src/modules/identity/internal/identity-service.ts`, `identity-repository.ts` | `apps/api/test/token-rotation.test.ts` | Refresh tokens are hashed (SHA-256) before database storage. Rotation flags prior token upon single use. Token family reuse detection automatically detects replay attacks and revokes all tokens within that family immediately. |
| **5. Role-Based Access Control (RBAC)** | `apps/api/src/modules/identity/rbac/policy.ts` | `apps/api/test/rbac.test.ts` | Explicit role-to-permission mapping for `ADMINISTRATOR`, `MERCHANT`, and `CUSTOMER`. Unauthorized operations strictly throw `ForbiddenError` (HTTP 403). |
| **6. Verified Tenant Isolation** | `apps/api/src/http/auth-middleware.ts`, `apps/api/src/modules/identity/rbac/policy.ts` | `apps/api/test/merchant-flow-isolation.test.ts` | Tenant context extracted strictly from verified server-side token; client cannot supply or tamper with tenant identifier. `requireTenantMatch` blocks cross-tenant resource reads and mutations. |
| **7. Merchant Onboarding & Profile Management** | `apps/api/src/modules/merchant/internal/merchant-service.ts`, `merchant-repository.ts`, `apps/api/src/http/merchant-routes.ts` | `apps/api/test/merchant-flow-isolation.test.ts` | Merchants can onboard profile (`POST /merchants/onboard`), retrieve profile (`GET /merchants/me`), and update profile details (`PATCH /merchants/me`) while in `DRAFT` status. |
| **8. Merchant Verification State Machine** | `apps/api/src/modules/merchant/internal/merchant-service.ts` | `apps/api/test/merchant-flow-isolation.test.ts` | Controlled lifecycle: `DRAFT` -> `SUBMITTED` -> `VERIFIED` / `REJECTED` -> `SUSPENDED`. Direct verification bypass attempts are rejected. Only platform `ADMINISTRATOR` can approve or reject. Once verified, profiles are immutable to merchant edits. |
| **9. Security Audit Logging** | `apps/api/src/modules/identity/internal/security-audit-service.ts` | `apps/api/test/merchant-flow-isolation.test.ts` | Append-only logging of `LOGIN_SUCCESS`, `LOGIN_FAILURE`, `REFRESH_TOKEN_ROTATED`, `REFRESH_TOKEN_REUSE_DETECTED`, `MERCHANT_VERIFICATION_APPROVED`, and `MERCHANT_VERIFICATION_REJECTED` with sensitive data redaction. |
| **10. Strict Architectural Boundary Enforcement** | `apps/api/src/architecture/boundary-rules.ts`, `apps/api/src/modules/identity/index.ts`, `merchant/index.ts` | `apps/api/test/architecture.test.ts` | Public interfaces only between bounded contexts. No cross-module imports into `internal/` directories. Zero domain coupling to HTTP framework. Zero architecture violations in codebase. |
| **11. Architecture Decision Records (ADRs)** | `docs/adr/0009-authentication-and-token-rotation.md`, `0010-rbac-and-tenant-isolation.md`, `0011-merchant-onboarding-verification.md` | Document review | Complete documentation of architectural context, decisions, positive/negative consequences, and alternatives considered for Phase 2. |
