## 2. Hardening Measures Implemented During Audit

1. **Live Actor & Membership Resolution**:
   - Implemented `IdentityService.resolveActiveActor` and connected it to `createAuthMiddleware`.
   - Verified that deactivated users (`status = 'DEACTIVATED'`), locked users (`status = 'LOCKED'`), suspended memberships (`status = 'SUSPENDED'`), and demoted roles are immediately rejected on protected routes rather than trusting stale JWT claims.
2. **Concurrency-Safe Refresh Token Rotation**:
   - Upgraded `IdentityRepository.rotateRefreshTokenAtomic` using an atomic conditional SQL update.
   - Wrapped refresh processing in `db.withTransaction` ensuring concurrent reuse attempts atomically trigger token-family revocation without duplicate token issuance.
3. **Authentication Endpoint Rate Limiting**:
   - Created `InMemoryRateLimiter` and attached pre-handler hooks to `/auth/register`, `/auth/login`, and `/auth/refresh` returning `429 Too Many Requests`.
4. **Platform Administrator vs Merchant Tenant Isolation**:
   - Enforced explicit checks preventing platform administrators from verifying their own tenant as a merchant.
5. **Accurate Audit Log Terminology**:
   - Removed all inaccurate claims of "tamper-evident" audit logs; updated all docstrings, migrations, and ADRs to describe the system accurately as an append-only audit log table.
6. **Architecture Boundary Test Strengthening**:
   - Added explicit boundary verification tests ensuring `Identity` and `Merchant` internals remain fully isolated from each other and future modules.
